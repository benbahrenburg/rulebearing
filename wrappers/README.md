# Wrappers

Thin shells over the one static binary ([architecture § Distribution](../docs/architecture.md#distribution), [ADR-0002](../docs/adr/0002-rust-as-implementation-language.md), [ADR-0020](../docs/adr/0020-single-name-across-registries.md)). Each wrapper carries the platform binary and nothing else, has its own test suite with a 70% line-coverage floor ([ADR-0018](../docs/adr/0018-test-coverage-threshold.md)), and is published from [release.yml](../.github/workflows/release.yml) with the same version as the binary.

| Directory | Registry | Package | Lands in |
| --- | --- | --- | --- |
| [npm/](npm/README.md) | npm | `rulebearing`, a launcher over six unscoped platform packages `rulebearing-cli-<platform>` under `optionalDependencies`; it also exports the `rulebearing/vitest` entry point built from [adapters/vitest](../adapters/vitest/README.md) | [Wave 1, 1G, Step 19](../docs/plans/pending/0001-wave-1-typescript-parity.md#step-19-npm-package-github-action-release-1g) |
| [nuget/](nuget/) | NuGet | `Rulebearing` as a `dotnet tool`, binary under `runtimes/` | [Wave 2, 2H](../docs/plans/pending/0002-wave-2-dotnet-python-element-rules.md) |
| [pip/](pip/README.md) | PyPI | `rulebearing` wheel per platform, binary in the package data, console script `rulebearing`; `pytest-rulebearing` ([adapters/python](../adapters/python/README.md)) depends on it | [Wave 2, 2H](../docs/plans/pending/0002-wave-2-dotnet-python-element-rules.md) |

The npm wrapper is the real package: its launcher, tests and staging script are described in [npm/README.md](npm/README.md), and [release.yml](../.github/workflows/release.yml) stages, install-checks and publishes it from the release archives ([docs/release.md](../docs/release.md#the-npm-wrapper-from-wave-1)). The PyPI wrapper is the real package too: one wheel per platform with the binary in the package data ([pip/README.md](pip/README.md)), built, install-checked and published by [release.yml](../.github/workflows/release.yml) ([docs/release.md](../docs/release.md#pypi-from-wave-2)). The NuGet wrapper is the real package as well: the `Rulebearing` dotnet tool, a launcher over the six binaries under `runtimes/<rid>/native/` ([nuget/README.md](nuget/README.md)), which release.yml packs through `pack.sh` together with the seven `Rulebearing.TestAdapter` packages, install-checks and publishes ([docs/release.md](../docs/release.md#nuget-from-wave-2)). [`crates/rulebearing/`](crates/rulebearing/README.md) is the crates.io reservation. [`publish-placeholders.sh`](publish-placeholders.sh) published all four reservations on one day ([Wave 0, 0E](../docs/plans/pending/0000-wave-0-spike.md); the procedure is in [docs/release.md](../docs/release.md)); its npm, PyPI and NuGet steps now only report the reservation (a real run refuses at the npm step rather than publish the real wrapper), so it is not rerun for any of them.
