Write a first configuration from what the repository holds, passing on its first run

Usage: rulebearing init [OPTIONS]

Options:
      --preset <PRESET>
          Presets to use: languages (typescript, dotnet, python) replace the ones found; frameworks
          (nextjs, clean-architecture, django, fastapi, vertical-slices), opinions that are off
          unless named, are added (repeat, or separate with commas)

          Possible values:
          - typescript:         TypeScript and JavaScript: `rulebearing:typescript`
          - dotnet:             .NET: `rulebearing:dotnet`
          - python:             Python: `rulebearing:python`
          - nextjs:             Next.js route and server boundaries: `rulebearing:nextjs`
          - clean-architecture: Domain, Application, Infrastructure and Presentation:
            `rulebearing:clean-architecture`
          - django:             Django's models, views, URLs and migrations: `rulebearing:django`
          - fastapi:            FastAPI's routers, services and repositories: `rulebearing:fastapi`
          - vertical-slices:    Features independent of each other: `rulebearing:vertical-slices`

      --dry-run
          Print the proposal and do not write it

      --force
          Replace an existing configuration file

      --output <FILE>
          Where to write the configuration
          
          [default: rulebearing.yaml]

      --expires <DATE|DAYS>
          When baseline entries expire: a date (YYYY-MM-DD) or a number of days

      --owner <OWNER>
          Who answers for baseline entries (default: the git user)

  -h, --help
          Print help (see a summary with '-h')
